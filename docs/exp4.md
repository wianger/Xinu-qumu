### 2.3 实现用户态 shell 命令 xsh_lab4，应完成如下要求：

**a.** `xsh_lab4` 命令运行于用户态（应通过调试等方式展示该函数的指令运行于用户态）

**b.** `xsh_lab4` 中定义一个局部变量，然后输出该变量的地址，根据传入的参数调用自己实现的用于测试 fork/exec 的函数（名称自拟），最后输出学号和姓名（如果中文显示有误，可使用拼音）。如：

```c
// 请自行保证代码正确性
int32 x;
printf("&x=0x%x\n", &x)
if (strcmp(argv[1], "1") == 0)
    fork_test1(潜在参数);
else
    fork_test2(潜在参数);
printf("<学号> <姓名>\n");
```

**c.** 不同场景下的 `fork_test` 应至少包含如下功能：

- 一种模式下，fork 得到的子进程不执行 exec，而是执行与父进程一样的代码，该代码中至少输出当前进程 PID、进程名和某个局部变量或参数的地址
- 另一种模式下，fork 得到的子进程执行 exec（需另提供一个子进程入口函数），父进程和子进程中至少输出当前进程 PID、进程名、所在函数名和某个局部变量或参数的地址

**d.** 在 `xsh_lab4` 运行期间，查看内存映射情况（QEMU 控制台命令：`info mem`）

**e.** `xsh_lab4` 及各子进程正常执行结束后，正确销毁该进程占用的内存空间，将页目录、页表、栈等空间释放掉，以为其他进程所用

**f.** 在进程创建和销毁过程中，输出为其分配和释放的内存页物理地址（或页编号），并说明各个物理页的用途，结合 d 中的内存映射情况说明每个物理页在 lab4 进程中的逻辑地址

**g.** 再次执行相同的 `lab4` 命令，查看对比此次执行过程分配释放的内存页（及各页的用途）与上一次执行的区别与联系

**h.** 在非调试状态下，shell 中执行 `lab4` 命令及各子进程能够正常结束

### 2.6 其他说明

**a.** 可以采用与课堂讲述的 Xinu-vm 参考实现不一样的实现方式，在实验报告中详细说明设计思路与实现细节（包括内存布局的设计——如果完全与 Xinu-vm 参考实现一致，内存布局的设计不用提供太多细节）

**c.** 进程的用户栈空间可以位于高地址处，也可以位于低地址处（在实验报告中清晰说明包含用户栈空间的进程内存布局——图示+文字）

**g.** 由于虚拟内存的引入，在未完全实现之前，可以将系统的大部分功能先去掉，再根据所实现的功能逐步开放。如：一开始可以将 `nulluser()` 中所有代码注释掉，添加少许代码验证虚拟内存是否正常开启；然后开启其他功能，验证新进程是否正确运行在虚拟内存空间（内核态进程、用户态进程）；检查进程正常运行结束，进程内存空间是否正确释放。【此处只是开展实验、编写代码的一种建议，不是强制要求】
