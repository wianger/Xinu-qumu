## 实验目的

希望学生能掌握内核态与用户态之间控制转移的实现，将 Xinu 转化为一个更为现代化的操作系统内核。

---

## 实验要求

### 实现用户态 shell 命令 `xsh_lab3`，应完成如下要求：

**a.** `xsh_lab3` 命令运行于用户态（应通过调试等方式展示该函数的指令运行于用户态）

**b.** `xsh_lab3` 可以创建另一个**用户态的进程** `uptest(int32, int32)`，uptest 进程工作流程如下所示，但应注意创建用户态进程的功能应是一般化的，而不是只能针对这里的 uptest（uptest 函数实现在 `xsh_lab3.c` 中）

```
输出进程 ID 和第 1 个参数，如 printf("proc=%d: a=%d", getpid(), a)
睡眠一段时间（不少于 1 个时间片）
输出进程 ID 和第 2 个参数，如 printf("proc=%d: b=%d", getpid(), b)
```

**c.** `xsh_lab3` 中至少以不同参数创建并启动 uptest 进程 3 次

**d.** `xsh_lab3` 返回前输出学号和姓名（如果中文输出乱码，可使用拼音；具体如何实现输出，不做任何限制，但应在实验报告中明确说明）

**e.** `xsh_lab3` 和 uptest 均以 `return` 正常结束（不能以无限循环或是绕过 return 的函数调用结束）

**f.** 调试状态下，能查看到用户态进程的正确的进程名称；或者直接在用户进程中输出进程名称。以截图方式呈现在实验报告中

**g.** 在非调试状态下，shell 中执行 `lab3` 命令能够正常结束

### （扩展要求，不强制）

将 main、shell 和至少 echo、ps、help 这三个命令变成用户态进程

### 其他说明

**a.** 所有用户态进程的优先级为 `INITPRIO`（20），内核态栈为 4KB，用户态栈为 8KB

**b.** 由于 Xinu 无法有效区分开内核态代码/数据和用户态代码/数据，可以在进入用户态进程之后认为所有全局变量都是用户态可访问的，但**在本实验中，用户态最多只允许访问 `xsh_lab3.c` 中定义的全局变量和 Xinu 的进程表项**（用于 2.1.f 中输出进程名）

**c.** 创建用户态进程的函数调用与原来创建进程的函数调用 `create` 保持一样的参数列表（即使优先级和栈大小这两个参数可能没有实际作用），但可以是另外实现的函数（如 `create_user_proc` 专门用于创建用户态进程，而不修改原 `create` 的代码）。应在实验报告中明确说明创建用户态进程的函数以及工作流程（与原有 `create` 中类似的操作可以简略）。也可以选择修改 `create` 函数，使其既能创建用户态进程，也能创建内核态进程。

**d.** 建议实现顺序：
1. 首先使一个没有任何具体功能的特定函数能进入用户态
2. 然后在该函数中添加循环，使其能正确的通过时间片轮转实现调度
3. 添加输出功能的系统调用相关实现
4. 添加或修改创建并启动一般化用户态进程的功能
5. 添加用户态进程正常退出的功能，并去除用户态进程函数中的循环

各位同学可根据实际情况自行决策如何完成。
